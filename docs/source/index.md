# Source guide

<p class="lede">Every address here has been checked against the running game. The pages are generated by re-disassembling the original listings from curated entry points, so a page shows the real instruction stream rather than a linear sweep's guess.</p>

## How to read a listing

Each line is an instruction: its address, its bytes, the mnemonic and operand, and a comment naming the routine or variable it touches. Gaps between blocks are branch targets that follow an early `RTS`; the game reaches them, the linear listing just could not show them in place.

The `Calls` and `Called by` sections are built by decoding every line start in the listings and keeping the `JSR`/`JMP` instructions that land on a known entry. Some call sites live in code the sweep never decoded, so the lists are a good map, not proof of a complete one.
